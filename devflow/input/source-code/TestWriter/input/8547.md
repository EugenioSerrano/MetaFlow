# US 8547 - [APROSS] Pagar con QR - 1.0

## Description

### Narrativa
**Como** Team Analyst, **Quiero** que se implemente el flujo de Pago con QR con validación de beneficios Apross, **Para** que el sistema verifique las reglas de negocio y otorgue el reintegro automáticamente en las transacciones válidas.

### Objetivo
Implementar el flujo de Pago con QR integrado con beneficios Apross, permitiendo identificar afiliados, validar prestadores y aplicar reintegros en transacciones elegibles (monto fijo de $4000), gestionando tanto QRs estáticos como dinámicos y asegurando la correcta actualización del contador de reintegros y la visualización de los estados de éxito o error según la configuración de cashback.

### Alcance — Incluye
- Implementación del flujo de pago con QR dinámico
- Integración con validación de beneficios Apross
- Gestión de QR estático (monto manual)
- Actualización del contador de reintegros
- Mensajes y pantallas de confirmación
- Manejo de estados de éxito/error según configuración de cashback

### Alcance — Excluye
- Cambios en la arquitectura de pagos no relacionados a Apross
- Modificación de reglas de negocio de otros beneficios
- Cambios en la configuración de permisos del dispositivo

### Reglas de Negocio
1. Monto fijo de reintegro: $4000
2. Límite de reintegros mensuales: máximo 3 por usuario (RULE_APROSS)
3. Validación de afiliado: usuario debe estar activo en Apross
4. Validación de prestador: comercio debe estar habilitado en BD local
5. Saldo suficiente: usuario debe tener saldo disponible para completar la transacción
6. Actualización de contador: debe decrementarse el contador disponible tras cada transacción exitosa
7. Confirmación diferida: reintegro se acredita en 48hs sujeto a aprobación de Apross

### Notas Técnicas
- Servicio principal: `AprossService.aprossBenefit`
- Pantallas afectadas: 9.1.1 - Pagar con QR (muestra reintegro Apross), 9.1.2 - Éxito (confirmación final)
- Contador de reintegros: fórmula = 3 - usos - 1
- Base de datos local: contiene registro de prestadores habilitados

## Acceptance Criteria

### AC 1: Pago exitoso con QR Dinámico y aplicación de beneficio Apross

**Dado** que el usuario es un afiliado activo de Apross
**Y** el comercio (prestador) está habilitado en la base de datos local
**Y** el usuario tiene menos de 3 reintegros utilizados en el mes (RULE_APROSS)
**Y** el usuario escanea un QR Dinámico desde la Home Bezza
**Y** posee saldo suficiente en su cuenta

**Cuando** el sistema procesa la validación a través de `AprossService.aprossBenefit`

**Entonces** el sistema debe mostrar la pantalla 9.1.1 - Pagar con QR con el mensaje de Reintegro Apross
**Y** al presionar "Pagar", se debe ejecutar el virtualizador de pago y finalizar con la pantalla 9.1.2 - Éxito
**Y** el mensaje de confirmación debe decir: "Reintegro en 48hs sujeto a aprobación de apross. Ver Términos y Condiciones."
**Y** el contador de beneficios debe actualizarse (remaining = 3 - usos - 1)
