---

## 1. Description

The kit's vocabulary and agent surfaces express the Actor concept: the
glossary and ONBOARDING define "Actor" as the umbrella term; the four
platform agents state the concept in their AITL sections while staying
byte-identical in their shared methodology regions (G-count 39×5,
verified with the US-016 audit tool); and the Actor phrase-family sweep
(ADR-005 discipline) verifies, as an absence over a fixed location set
with an allowlist, that no stale or competing terms remain.

---

## 2. Expected outcome and completion evidence

- **Objective:** every surface that names the concept speaks one
  consistent vocabulary, and the concept is mechanically verified — the
  same discipline that caught three misses during US-020 and guided the
  US-021 sweep.
- **Completion criterion:** glossary + ONBOARDING contain the "Actor"
  entry; the four platform agents' shared bodies state the concept and
  remain byte-identical (G-count invariant holds); the phrase-family sweep
  — run **last**, over a location set that includes the `actors/` README
  (BOLT-002) — finds no stale/competing terms outside the declared
  allowlist.
- **Expected evidence:** diff of the glossary, ONBOARDING and the four
  platform agent files; the US-016 audit output (four-agent sync + G-count
  39×5); the sweep report (location set, allowlist, absence result).
- **Scope:** the kit's glossary, ONBOARDING and the four platform agents
  (`CLAUDE.md`, `.agents/skills/avenga-devflow/SKILL.md`,
  `.github/agents/AvengaDevFlow.agent.md`,
  `.opencode/agents/AvengaDevFlow.md`), governed by the ADR-005 sweep.
- **Exclusions:** the §Actor normative text (BOLT-001); the `actors/`
  folder + README (BOLT-002); any guardrail added/removed (count
  invariant); recorded history (G36 — approved artifacts' recorded terms
  are never rewritten).
- **Risks / controls:** the four-agent sync breaking — controlled by the
  byte-identity + G-count invariants via US-016; an incomplete sweep —
  controlled by the ADR-005 absence discipline over a fixed location set
  with an allowlist.

---

## 3. Covered acceptance criteria

> Reference the ACs of the parent artifact — never write new ones here
> (§2.4, §2.6).

- `AC-6` (US-022) — **Given** the four platform agents, **When** they state
  the precept/AITL sections, **Then** they express the Actor concept and
  remain byte-identical in their shared methodology regions (G-count
  invariant holds) — verified with the US-016 audit tool.
- `AC-7` (US-022) — **Given** the vocabulary (glossary, ONBOARDING),
  **When** the kit defines terms, **Then** "Actor" is defined as the
  umbrella term covering humans and DevFlow Agents, consistent with the
  pure v5 vocabulary (ADR-010).
- `AC-11` (US-022) — **Given** the Actor vocabulary family ("Actor",
  "Actor-in-the-Loop", "human-by-default, agent-by-explicit-configuration"),
  **When** the kit is swept, **Then** the phrase-family sweep (ADR-005
  discipline) covers it over a fixed location set with an allowlist,
  verified as an **absence** of stale/competing terms.
