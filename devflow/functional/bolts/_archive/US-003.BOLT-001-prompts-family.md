---

## 1. Description

Deliver the `devflow/prompts/` family in the distributable kit: a standalone
folder where an adopting team creates, modifies and improves its prompts
(`PROMPT-NNN-<description>.md`, sequential numbering), shares them through
the repository and version-controls them with git. Prompts are living data —
copy-paste usage, no approval and no manifest. The four agent definitions
learn to keep project prompts in that folder instead of `agents-data/`, and
the §5.15 migration routing carries the family across upgrades.

---

## 2. Expected outcome and completion evidence

- **Objective:** every adopting project receives the prompts family and the
  agent behavior that keeps prompts ordered in it.
- **Completion criterion:** the kit contains the folder, the template, the
  README (copy-paste convention) and the INDEX; the naming convention
  `PROMPT-NNN-<description>.md` is documented; the four agent definitions
  contain the identical prompts sentence in the §5.12 working-data
  paragraph; the §5.15 routing table lists the family.
- **Expected evidence:**
  - file-presence and naming checks (family files exist, template shape);
  - four-agent whole-body sync diff (2 lines of sanctioned divergence) and
    the identical prompts sentence present 4×;
  - §5.15 routing row present;
  - grep across the kit: prompts are never routed to `agents-data/`.
- **Scope:** the kit's `devflow/prompts/` family (template, README, INDEX,
  naming convention), the four-agent shared-body sentence, and the §5.15
  routing row.
- **Exclusions:** the product `prompts/` tree of this repository (untouched);
  any approval/manifest machinery for prompts; other kit families (roster,
  sprints) — separate USs.
- **Risks / controls:** 4-agent text drift — controlled by the sync-diff
  completion evidence; ambiguity between the product `prompts/` tree and the
  new family — controlled by explicit scope wording in the SPEC.

---

## 3. Covered acceptance criteria

- `AC-1` (US-003) — **Given** the kit, **When** a project wants a prompt —
  new, modified or improved — **Then** it has a canonical `devflow/prompts/`
  family with a template, README and INDEX.
- `AC-2` (US-003) — **Given** a new prompt, **When** it is created, **Then**
  it is named with sequential numbering like the US family
  (`PROMPT-NNN-<description>.md`).
- `AC-3` (US-003) — **Given** an existing prompt, **When** the team asks the
  agent to modify or improve it, **Then** the updated version lands back in
  the same folder, never in `agents-data/`.
- `AC-4` (US-003) — **Given** a prompt in the folder, **When** the team works
  with it, **Then** it is shared and version-controlled through the
  repository.
- `AC-5` (US-003) — **Given** a prompt file, **When** someone uses it, **Then**
  its body is copied and pasted directly into the agent — no approval, no
  manifest, no governance ceremony.
- `AC-6` (US-003) — **Given** the four agent definitions, **When** they
  reference project prompts, **Then** they point at `devflow/prompts/`
  (4-file sync).
- `AC-7` (US-003) — **Given** a methodology upgrade, **When** the project
  migrates, **Then** the prompts family travels with the migration (§5.15
  routing covers it).
