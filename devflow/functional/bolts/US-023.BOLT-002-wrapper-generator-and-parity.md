---

## 1. Description

The kit's tooling gains the **wrapper generator** in `tools/`: a
maintainer-run generator that projects a canonical DevFlow Agent definition
(`agents/roles/<id>/agent.yaml`) into the four platform wrapper shapes
(Claude Code `.claude/agents/*.md`, OpenCode `.opencode/agents/*.md`,
GitHub Copilot `.github/agents/*.agent.md`, Codex `agents/*.toml`), plus
the **N×4 parity check** — the four-agent sync philosophy extended to N
roles × 4 platforms — integrated with the US-016 audit tool so the parity
invariant is mechanically verified.

---

## 2. Expected outcome and completion evidence

- **Objective:** a repeatable generator + a parity gate that keeps the
  canonical definitions and the four projections from drifting.
- **Completion criterion:** the generator runs from the canonical
  definitions; the N×4 parity check passes and is wired into the US-016
  audit surface (or reported as a compatible extension of it).
- **Expected evidence:** the generator run output (the four wrapper shapes
  per role); the parity check result (N×4 consistent, 0 drift);
  integration evidence with US-016.
- **Scope:** `tools/` (the generator + the parity check) — kit tooling.
- **Exclusions:** the wrapper files themselves (generated + committed in
  BOLT-003); the canonical definitions (BOLT-001); the per-platform
  verification notes (BOLT-003); the root `devflow/` (ADR-004).
- **Risks / controls:** generator drift from the platform contracts —
  controlled by the parity check + the per-platform re-verification in
  BOLT-003 (DISC-002 rec #6).
