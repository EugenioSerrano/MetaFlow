---

## 1. Description

The v5.1 kit's core methodology states the **Actor** concept normatively in
its §Actor section: the definition (human by default / DevFlow Agent by
explicit valid configuration; the executor/approver/neither relationship),
the actor grammar, the two independence layers, the open role taxonomy, the
safe default, the canonical Actor flow diagram (mermaid) and the `actors/`
entry in the canonical folder tree (§5.1).

---

## 2. Expected outcome and completion evidence

- **Objective:** the core methodology document carries the normative Actor
  definition — the single source of truth that the `actors/` README
  (BOLT-002), the agent definitions (US-023) and the roster (US-024)
  reference.
- **Completion criterion:** the §Actor section exists with the six elements
  (definition, grammar, independence layers, open roles, safe default,
  canonical mermaid) and §5.1 lists `actors/`.
- **Expected evidence:** diff of `Avenga-DevFlow.md`; the §Actor section
  text present; the §5.1 tree excerpt showing the `actors/` entry.
- **Scope:** the kit's core methodology document only
  (`distribution-kit/devflow/avenga-devflow/Avenga-DevFlow.md`).
- **Exclusions:** the `actors/` folder + README (BOLT-002); glossary +
  ONBOARDING + the four platform agents + the phrase-family sweep
  (BOLT-003); any manifest/schema change (US-022 AC-4 guard — the
  `checkpoint_approvals[]` record is landed and referenced, not modified);
  no guardrail added/removed (count invariant).
- **Risks / controls:** overlap with already-landed grammar (US-020 /
  ADR-010 Bolts) — controlled by the AC-4 scope guard; inconsistent
  concept wording — controlled by the canonical single-source rule (the
  README in BOLT-002 points here, never forks).

## 3. Covered acceptance criteria

> Reference the ACs of the parent artifact — never write new ones here
> (§2.4, §2.6).

- `AC-1` (US-022) — **Given** the kit's core methodology, **When** it
  states the precept, **Then** it defines the Actor (human by default /
  DevFlow Agent by explicit valid configuration; executor/approver/neither
  relationship, Coordinator-never-signs umbrella).
- `AC-2` (US-022) — **Given** the identity model, **When** the kit
  describes actors, **Then** identity belongs to the actor, not the model
  (`human:<user>` / `agent:<id>`; model as attribute).
- `AC-3` (US-022) — **Given** the two independence layers, **When** the kit
  states approval independence, **Then** actor floor / model hardening at
  `high` / human ceiling at `critical`-`regulatory`.
- `AC-4` (US-022) — **Given** the v5 manifest record, **When** a
  checkpoint approval is recorded, **Then** this US makes no schema change
  — it references the landed record.
- `AC-5` (US-022) — **Given** the safe-default invariant, **When** no
  virtual agent is configured, **Then** every checkpoint resolves to a
  human actor (zero-config = pure HITL).
- `AC-10` (US-022) — **Given** the role taxonomy, **When** the kit names
  roles, **Then** role is an open archetype (recommended examples, not a
  closed enum); independence on the actor `id`, never on the role taxonomy.
