## 1. Description

The comprehensive, final sweep of US-021: rename the pervasive **`HITL` adjective**
(cat 2 — "HITL approval", "HITL checkpoint", "HITL governance", …) **and** every
**`HITL-<CODE>-Approval` identifier** (cat 3 — ~1,119, incl. the §3.0 charter table,
the canonical naming rule, and the `DISC`/`REV`/`AREV` variants) to **AITL**,
kit-wide, under the ADR-005 phrase-family discipline. Preceded by BOLT-001
(concept), BOLT-002 (guardrails scoped), BOLT-003 (schema accepts `AITL-*`) — so the
renamed identifiers validate.

---

## 2. Expected outcome and completion evidence

- **Objective:** the v5.0 kit speaks AITL end-to-end — concept, guardrails, schema
  (done) **and now every checkpoint identifier and every `HITL` adjective** — while
  legitimately-preserved `HITL-*` (history, migration source) stays.
- **Completion criterion:**
  - **Cat 3 (identifiers):** every canonical `HITL-<CODE>-Approval` →
    `AITL-<CODE>-Approval` (all eight core + `DISC`/`REV`/`AREV-*` variants), incl.
    the §3.0 charter table and the canonical naming rule.
  - **Cat 2 (adjective):** the `HITL` shorthand → AITL where it names the current
    concept ("AITL approval", "AITL checkpoint", "AITL Coverage", …).
  - **Allowlist — `HITL-*` that MUST remain:** (a) the **§5.16 migration recipe** and
    its `HITL-*` history/`3.0→4.0`/`4.0→5.0` examples (G36 — history keeps `HITL-*`);
    (b) the **manifest schema enums'** `HITL-*` entries (BOLT-003 — accept migrated
    history); (c) **G05/G18/G24** already scoped in BOLT-002 (they name `HITL-*` as
    legacy on purpose); (d) the **four agents' Upgrade-Protocol notes** naming the
    v4 source; (e) the numbered **H1–H6** legacy aliases.
  - **Count/sync invariants:** blocking-rule count **39×5**; four-agent shared
    regions byte-identical.
- **Expected evidence:** the ADR-005 sweep (fixed location set = whole kit, phrase
  family, allowlist, phrased as an absence) returns **zero** non-allowlisted `HITL`
  adjective / `HITL-<CODE>-Approval` identifier; a migrated `HITL-*` manifest still
  validates (G36); G-count 39×5; four-agent sync; `git status` kit-only.
- **Scope:** every `.md` under `distribution-kit/` (concept done, but any remaining
  identifier/adjective) + the checkpoint identifiers wherever they appear.
- **Exclusions:** the schema enums' `HITL-*` entries (allowlist — BOLT-003 keeps
  them for history); G05/G18/G24 (allowlist — BOLT-002); the precept prose already
  done (BOLT-001); enabling virtual approvers / registry / roster / pilot (later
  USs); the root `devflow/` (ADR-004).
- **Risks / controls:** an over-broad sweep removes `HITL-*` history support →
  control: the allowlist + an AC that a migrated `HITL-*` manifest still validates;
  an incomplete sweep leaves stray `HITL` → control: the ADR-005 absence assertion
  over the whole kit (the discipline that caught three US-020 misses).

## 5. Does this Bolt need splitting?

No — one comprehensive ADR-005 sweep with one declared allowlist and one demo
criterion (zero non-allowlisted `HITL`). Splitting the adjective from the
identifiers is counter-productive (they interleave on the same lines). Large but
mechanical; est. ~4h (§2.4).
