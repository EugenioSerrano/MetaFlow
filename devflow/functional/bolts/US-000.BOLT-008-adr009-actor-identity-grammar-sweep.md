## 1. Description

Apply the actor record **grammar** (ADR-010 §3.1–§3.5) across the entire v5.0
kit (`distribution-kit/`), closing the grammar sites that approved **REV-003**
inventoried (F-01…F-05, F-08). Today identity is recorded in three inconsistent
grammars (actor-shaped only in `checkpoint_approvals[].decided_by[]`; user-shaped in
the review contract; bare-human in `created_by` and ~35 frontmatter fields). This Bolt
makes it **one**: `human:<user>` | `agent:<id>`, prefix-mandatory in machine records
and review/enforcement fields, bare-as-human shorthand in descriptive frontmatter.
**No new decision is introduced** — ADR-010 already governs the target state; this is
its mechanical application in one allowlist-aware pass. The **vocabulary purge**
(dropping `HITL-*` from the checkpoint enum and rewriting names on migration, ADR-010
§3.6–§3.7) is the sibling Bolt US-000.BOLT-009, run after this one — they touch the
same schema files, so they are sequenced, never concurrent (G11/§3.2). The window is
pre-release (REV-003 F-07): the reshape folds into the not-yet-shipped v5 family at
zero migration cost.

## 2. Expected outcome and completion evidence

- **Objective:** every recorded identity in the kit uses ADR-010's grammar
  (§3.1–§3.5), and the artifact↔manifest review projection becomes a field-for-field
  copy.
- **Completion criterion — each REV-003 finding closed:**
  - **F-01** — the review contract records actors: `reviewers: [{actor, role, model}]`
    (the `decided_by[]` shape) in the §3.0 normative example, `GUARDRAILS.md`, W11,
    and all 16 template review/acceptance blocks; `risk_history[].decided_by[]` follows.
  - **F-02** — `generation.created_by` is actor-shaped (prefix-mandatory), and every
    `runs[]` entry carries `agent` (nullable: `null` when not agent-executed, the agent
    `id` when it was), in the 3 schemas, the 5 manifest examples and §3.12.
  - **F-03** — §3.0 defines identity as two namespaces (`human:<git-email-local>` |
    `agent:<id>`) with the bare-as-human normalization rule; the ~35 frontmatter person
    comments (`author:`/`owner:`/`validator:`/`closed_by:`/`facilitator:`) note the
    shorthand.
  - **F-04** — `checkpoint_approvals[].mode` is **removed** (derived from the actor
    prefixes, G39) in the 3 schemas, the manifest examples, §3.12 and the four agents.
  - **F-05** — `$defs.hitlSubject` → `checkpointSubject` in the v5 Bolt schema (+ its
    reference).
  - **F-08** — the kit cites the methodology anchor (§3.0 charter) instead of the
    maintainer-repo ids `ADR-007`/`ADR-008` (GUARDRAILS G18, the four agents, kit
    `AGENTS.md`, `spec/README.md`).
  - **Not here (BOLT-009):** the checkpoint enum stays as-is in this Bolt; dropping its
    `HITL-*` values is ADR-010 §3.6 → US-000.BOLT-009.
- **Conversion (§5.16, G36):** the `4.0`→`5.0` conversion table in §5.16 gains this
  Bolt's **grammar** reshapes (`reviewers`→actor, `created_by`→`human:<u>`, `runs[]`
  gains `agent: null`, no `mode` written); recorded history is never rewritten. The
  **checkpoint-name rewrite** (`HITL-*`→`AITL-*`) row is added by BOLT-009 (ADR-010 §3.7).
- **Expected evidence (in the MEM):** the zone-scoped absence sweep = **zero**
  old-grammar residue kit-wide (`\[{user, role}\]`; bare unprefixed `created_by` in
  machine records; `mode` in `checkpointApproval`; `hitlSubject`; `ADR-007|ADR-008`
  cited in the kit); the **5** `TEMPLATE-MANIFEST-*.json` validate against the reshaped
  v5 schemas; a virtual approval example validates (`agent:<id>` reviewer/approver);
  four-agent shared-region byte-identity + G-count 39×5; `git status` shows only
  `distribution-kit/` + root governance records (kit-only, ADR-004).
- **Scope:** `distribution-kit/` only — the 3 schemas (`created_by` pattern,
  `runs[].agent`, drop `mode`, `hitlSubject`→`checkpointSubject` — **not** the
  `checkpoint` enum), 5 manifest examples, `Avenga-DevFlow.md` (§3.0/§3.3/§3.12/§5.16
  grammar rows), `GUARDRAILS.md`, the 16 template review blocks, the ~35 frontmatter
  comments, and the four agent definitions.
- **Exclusions:** the checkpoint enum's `HITL-*` values **and** the §5.16 name-rewrite
  → **US-000.BOLT-009** (ADR-010 §3.6–§3.7); AREV phase model fields
  (`challenger_model`/`defender_model`/`judge_model` — G37, model-based by design);
  `git config user.email` as the *source* of the human namespace; role/domain fields
  (`role`, `decision_makers`, `participants`, `stakeholders`, `real_name`); approved
  MEM/ADR bodies (G36); the root `devflow/` tree (ADR-004); **building** the agent layer
  (roster/Coordinator/registry — later USs).
- **Risks / controls:** schema reshape breaks example validation → validate all 5 in the
  MEM; over-broad sweep touches AREV model fields or history → zone-scoped exclusion +
  explicit scope guards (F-06); four-agent drift → byte-identity + G-count 39×5;
  file overlap with the (Done) BOLT-007 edits → none active, BOLT-007 closed.

## 5. Does this Bolt need splitting?

Split **once**, along the ADR boundary: this Bolt is the **grammar** (ADR-010 §3.1–§3.5,
REV-003 F-01…F-05/F-08) and **US-000.BOLT-009** is the **vocabulary purge** (ADR-010

by different clauses, and the purge depends on this Bolt's reshaped schemas being in place
first. Within this Bolt no further split: schema + examples + prose + agents move together
and share one completion demo (zone-scoped absence sweep + 5-example schema validation +
four-agent parity); F-08 touches the same files (GUARDRAILS, agents) so it stays here.
Estimated active delivery (AI-native rule, §2.4): one V-Bounce, ~2–4h including SPEC +
