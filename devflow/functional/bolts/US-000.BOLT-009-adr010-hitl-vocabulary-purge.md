---

## 1. Description

Make the v5 record vocabulary pure, per **ADR-010 §3.6–§3.7**: remove the `HITL-*`
values from the `checkpoint` enum of the three `manifest-v5-*.schema.json`, and rewrite
the §5.16 `4.0`→`5.0` conversion so that migration **re-expresses** each historical
checkpoint name in the current vocabulary (`HITL-<CODE>-Approval` → `AITL-<CODE>-Approval`)
instead of preserving it. Backward compatibility stays where it belongs — the **frozen v4
schema**, which keeps `HITL-*` because it *is* v4. **No new decision is introduced** —
ADR-010 governs the target state; this is its mechanical application. Runs **after**
US-000.BOLT-008 (which reshapes the grammar defs of the same schemas), so the enum is the
only remaining v5-schema change.

---

## 2. Expected outcome and completion evidence

- **Objective:** a v5 manifest never carries a `HITL-*` checkpoint name; the v5 schema
  declares only the current vocabulary; migration adapts the data, not the schema.
- **Completion criterion (ADR-010 §3.6–§3.7):**
  - the `checkpoint` enum of all 3 `manifest-v5-*.schema.json` lists **only** the
    `AITL-*` identifiers — the `HITL-*` values are removed;
  - §5.16's conversion text changes from "preserve HITL-* names verbatim" to "rewrite
    `HITL-*`→`AITL-*` (the decision — actor/timestamp/outcome/mode — is immutable; only
    the vocabulary label tracks the version; AITL ⊇ HITL, so the label becomes truer, G36);
  - any prose that described the enum as accepting both (e.g. the ADR-009-era wording, if
    any residue remains after BOLT-008) is corrected;
  - G05's treatment: `HITL-*` is absent from v5 records entirely (not merely "invalid for
    new").
- **Expected evidence (in the MEM):**
  - `grep` for `HITL-` in the 3 v5 schemas' `checkpoint` enums → **0**;
  - a **migration round-trip test**: a v4 manifest carrying `HITL-MEM-Approval` +
    `{user,role}` converts to a v5 manifest carrying `AITL-MEM-Approval` +
    `{actor:"human:<u>", role, model:null}`, which **validates against the pure v5 schema**
    and contains **zero** `HITL-*`;
  - the 5 `TEMPLATE-MANIFEST-*.json` (already AITL-*) still validate against the purified
    schemas;
  - `git status` shows only `distribution-kit/` + root governance records (kit-only, ADR-004).
- **Scope:** `distribution-kit/` only — the `checkpoint` enum of the 3
  `manifest-v5-*.schema.json`, and the §5.16 conversion text in `Avenga-DevFlow.md`
  (+ the four agents' §5.16 mapping mention if it states the preservation rule).
- **Exclusions:** the grammar defs (BOLT-008's territory — `created_by`, `runs[].agent`,
  `mode`, `hitlSubject`); the **v4** schemas (frozen, keep `HITL-*` by design); recorded
  v4.2 history in this maintainer repo (ADR-004/006 — its own governance stays HITL-* while
  it dogfoods); the root `devflow/` tree.
- **Risks / controls:** removing enum values breaks a manifest that legitimately used them →
  none in the kit (examples are AITL-*); the migration round-trip test proves converted
  history validates → covers the G36 concern; running before BOLT-008 Done → forbidden
  (sequencing dependency).
