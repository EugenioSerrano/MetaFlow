## 1. Description

Evolve the **Human-in-the-Loop concept** of the v5.0 kit into **AITL
(Actor-in-the-Loop)** — the conceptual heart of ADR-008 §3.1. Reframe §0's precept
from *"the AI generates, the human governs at every checkpoint"* to
**"human-by-default, agent-by-explicit-configuration"**, and define the actor (a
human by default, or a virtual DevFlow Agent by explicit valid configuration).
Apply the same conceptual evolution to the four platform agents' concept
sections. This is prose/definition work; the mechanical identifier rename is
BOLT-004.

---

## 2. Expected outcome and completion evidence

- **Objective:** an adopter reading the v5.0 kit's core methodology understands the
  paradigm as AITL — every checkpoint is still a mandatory pause, occupied by an
  **actor** that is a human by default and a virtual DevFlow Agent only by
  explicit valid configuration.
- **Completion criterion:**
  - The core methodology's paradigm statement (§0 and the "Human-in-the-Loop"
    conceptual section) reads the **AITL precept**: human-by-default,
    agent-by-explicit-configuration; defines **AITL = Actor-in-the-Loop** and the
    **actor** (human or DevFlow Agent, ADR-007); states HITL as the **default
    case** (actor = human) inside AITL, not a separate paradigm.
  - The **safe-default invariant** is stated conceptually (no/invalid config →
    pure HITL; no AI-signed approval possible) (ADR-008 §3.2).
  - The four platform agents' concept sections carry the same AITL framing,
    byte-identical in their shared regions.
- **Expected evidence:** the reframed §0/concept text; four-agent sync of the
  shared concept region + G-count unchanged; `git status` shows only
  `distribution-kit/`; **no `HITL-<CODE>-Approval` identifier changed** in this
  Bolt (that is BOLT-004's scope — kept out to keep the boundary clean).
- **Scope:** the **concept** — the term "HITL"/"Human-in-the-Loop" and the §0
  precept, in the core methodology + the agents' concept sections.
- **Exclusions:** the `HITL-<CODE>-Approval` **identifiers** (BOLT-004); GUARDRAILS
  scoping G05/G18/G24 (BOLT-002); the schema enum (BOLT-003); enabling virtual
  approvers / registry / Coordinator / roster / pilot (later USs); the root
  `devflow/` (ADR-004).
- **Risks / controls:** conflating the concept term with the identifiers →
  control: the SPEC declares the concept-vs-identifier phrase-family boundary
  (ADR-005), and an AC asserts **zero** identifier changes here; diluting a
  guarantee while reframing → control: the reframe states the safe-default
  invariant explicitly (ADR-008 §3.2) and changes no pause.
