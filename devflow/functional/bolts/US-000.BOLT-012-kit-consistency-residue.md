## 1. Description

Apply the six localized consistency corrections evidenced by REV-004
F-02..F-07 (plus the optional cosmetic F-08), so the kit's normative prose
and summaries agree with the kit's own rules:

- **F-02 — §3.9 Dev-validator role:** remove the clause "never one they
  themselves drafted or authored" from the non-functional BUG approval
  description and align it to the pervasive rule (G29, §3.11, §2.16): any
  qualified team member, the BUG's own author included, may record
  `AITL-BUG-Approval` at any severity. **G29 itself is not modified** — this
  is alignment of a stale paragraph to the guardrail it contradicts.
- **F-03 — §0 Quick Start:** replace the absolute "A human checkpoint cannot
  be delegated to AI" with the AITL charter wording already used in
  `GUARDRAILS.md` ("a human **by default**, a virtual DevFlow Agent only by
  explicit, valid configuration; absent/invalid config → human-only, no
  AI-signed approval possible").
- **F-04 — `avenga-devflow/INDEX.md`:** remove `UNIT, UAT` from the named
  checkpoint enumeration — §3.0 defines exactly 13 codes; the Unit/UAT
  approval layer is dormant/removed.
- **F-05 — legacy-name prose (maintainer direction 2026-08-23: drop the
  v3-era `H1–H6` aliases):** remove every `H1–H6` mention from the kit's
  legacy-checkpoint prose **and** from the G05 rows (GUARDRAILS + the four
  agents' inline rows). The legacy set becomes solely the pre-v5 `HITL-*`
  prefix; the G05 rule keeps its enforcement (legacy and non-canonical
  checkpoint names are invalid for new approvals; the canonical 13-code list
  in §3.0 is the normative reference) and G-count stays 39. **Material scope
  change vs the approved scope (G15):** the remediation direction changed
  from "extend the prose with `HITL-*`" to "remove `H1–H6` kit-wide", and the
  G05 guardrail rows enter scope (previously excluded).
- **F-06 — `reviews/README.md` REV→BUG severity mapping:** reword "must
  reach an Architect/Tech Lead" to the recommended-approver phrasing per G29
  (the routing is guidance, never a gate).
- **F-07 — methodology §3.1 `llm` rule:** declare the AREV per-phase-model
  exception that GUARDRAILS W09 already enforces — the AREV phase templates
  record `challenger_model` / `defender_model` / `judge_model` and carry no
  separate `llm:` field.
- **F-08 (optional, fold in) — template placeholder links:** wrap the
  placeholder paths in `adversarial-reviews/TEMPLATE-AREV.md` and
  `functional/user-stories/TEMPLATE-US.md` in code spans so link checks stop
  flagging instantiation-time links.

No governance rule, checkpoint, guardrail or schema changes; G29 stays
exactly as written after US-000.BOLT-010.

## 2. Expected outcome and completion evidence

- **Objective:** every finding F-02..F-07 is resolved at its documented
  location, with F-08 folded in; the kit's summaries and prose no longer

- **Completion criteria:**

    human-by-default / explicit-valid-configuration wording of
    `GUARDRAILS.md`.

    phase-template exception explicitly.
