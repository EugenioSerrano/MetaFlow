# US-001.BOLT-002 — Verificador de tokens prohibidos + reporte + aceptación E2E

| Field        | Value |
|--------------|-------|

| **Demo / completion evidence** | Ejecución real completa: el pipeline falla si queda cualquier token prohibido en `distribution-kit/` y genera el reporte con reglas, conteos y remociones; la aceptación E2E contra el kit real pasa en cero |

---

## 1. Description

Entrega el verificador de tokens prohibidos (barrido del kit de salida —
contenido y rutas — con tokens exactos y variantes; el run falla y lista los
hits ante cualquier leftover), el reporte de transformación (reglas aplicadas,
conteos por regla, remociones listadas, cobertura por archivo) y la suite de
aceptación E2E contra el kit real (fixtures + `input-kit/` real, verificador
en cero). Además genera los **diffs por archivo** (original → convertido) y
persiste la evidencia completa del run en `transform-reports/<versión>/<run>/`
(reporte JSON+MD, diffs, lista de archivos sin cambios, log) para revisión
humana o análisis con IA posterior (R6).

---

## 2. Expected outcome and completion evidence

- **Objective:** garantizar cero contaminación de marca en `distribution-kit/`
  (O1 de la visión) y dejar evidencia persistente y re-analizable de cada
  transformación.
- **Completion criterion:** sobre el kit real transformado, el verificador
  termina en cero hits (exit 0); ante un leftover inyectado a propósito, el
  run falla (exit != 0) y lista el hit; el reporte del run contiene reglas
  aplicadas, conteos y remociones; la carpeta de evidencia del run contiene
  reporte (JSON+MD), diffs por archivo y lista de archivos sin cambios.
- **Expected evidence:** salida del verificador, reporte del run
  (`transform-report-<version>.json/.md`), carpeta `transform-reports/` con
  diffs y log, suite E2E en verde (fixtures y kit real).
- **Scope:** barrido de tokens prohibidos (exactos + variantes: case,
  plurales, URLs, copyright) sobre contenido y rutas del output, fallo del
  run con lista de hits, reporte de transformación, generación de diffs por
  archivo y persistencia de la evidencia (`transform-reports/`, nunca borrada
  automáticamente), fixtures E2E y aceptación contra el kit real.
- **Exclusions:** engine de reglas y CLI (BOLT-001).
- **Risks / controls:** BR-001 (contaminación de marca) → el verificador
  falla el pipeline ante cualquier leftover; falsos positivos (términos que se
  conservan por diseño: US, TC, ADR, SPEC, MEM, G01–G39…) → lista de términos
  conservados del glossary §7 como excepción del barrido.

---

## 3. Covered acceptance criteria

> ACs del parent — no se escriben ACs nuevas (§2.4, §2.6).

- `AC-7` (US-001) — **Given** un kit transformado, **When** corre el verificador, **Then** el run falla (exit != 0) y lista los hits si queda cualquier token prohibido; si no queda ninguno, el run es exitoso.
- `AC-8` (US-001) — **Given** una ejecución real, **When** termina, **Then** se genera el reporte con reglas aplicadas, conteos por regla y remociones listadas, como evidencia para revisión humana.
- `AC-9` (US-001) — **Given** el toolkit, **When** se ejecuta la suite de tests, **Then** pasa la aceptación E2E contra el kit real (verificador en cero); los unitarios del engine viven en BOLT-001.
- `AC-11` (US-001) — **Given** una ejecución real, **When** termina, **Then** la evidencia del run queda persistida en `transform-reports/<versión>/<run>/` (reporte, diffs por archivo, lista de sin-cambios, log).
