## 1. Description

The GitHub Copilot platform surface of the US-025 lifecycle is corrected
per REV-006 (approved 2026-08-25): an installed agent definition is
**spawnable by the Coordinator** on Copilot (the `agent` tool enabled in
the Coordinator's frontmatter), the **execution-evidence rule** is
stated (an author stamp is meaningful only with a real spawn trace), and
the **VERIFICATION.md Copilot row** is updated with the four platform
facts the smoke test established.

---

## 2. Expected outcome and completion evidence

- **Objective:** on GitHub Copilot (VS Code), the Coordinator can invoke
  installed role agents (US-025 AC-2 operational on the Copilot
  platform), and the kit's platform docs state the Copilot-specific
  behaviors the test measured.
- **Completion criterion:**
  1. The Copilot Coordinator's frontmatter `tools:` includes the
     platform's canonical agent-invocation alias (`agent`), so the body's
     spawn-topology claim ("Only your tools include the `agent` alias")
     is backed by configuration (REV-006 F-01).
  2. `agents/VERIFICATION.md` + the agents-family README state the
     **execution-evidence rule**: an executor's production may be
     persisted by the Coordinator, but the persistence act must trace to
     a real spawn — a stamp without execution is a false claim; when
     spawn is unavailable, direct human invocation is the only
     legitimate reviewer session (REV-006 F-02).
  3. The `VERIFICATION.md` Copilot row documents: (a) agent-initiated
     spawn requires the `agent` tool; (b) role wrappers are
     user-invocable by default — `user-invocable: false` for
     subagent-only visibility (REV-006 F-03); (c) validate the roster
     after an agent edit — the edit tool may write TAB indentation
     (REV-006 F-04); (d) the 30k prompt cap is cloud-agent scope —
     verified full-load on VS Code 2026-08-25, re-verify per environment
     (REV-006 F-05).
  4. The shared methodology body of the four agents is unchanged
     (the change is frontmatter/preamble-only on the Copilot file).
- **Expected evidence:** the four-agent sync diff (expected: 2 differing
  lines only — the sanctioned `agents-data/<agent>/` path); G-count
  grep 39/39; a re-run of the spawn probe on the Copilot adopter test
  project showing the delegated review executed by the reviewer (the
  `reviewer-copilot` pill), not self-executed by the Coordinator.
- **Scope:** the Copilot Coordinator frontmatter; `agents/VERIFICATION.md`
  (Copilot row + the execution-evidence rule); the agents-family README
  line for the execution-evidence rule.
- **Exclusions:** the other three platform files (no change); the
  reviewer charter/definition enrichment (REV-005 F-07's separate charter
  Bolt); the roster schema / `approves` enum (boundary resolved by
  maintainer decision at REV-005 routing); any 30k-related code change
  (no defect — wording only, REV-006 F-05).
- **Risks / controls:** shared-body drift — controlled by the
  four-agent sync diff gate (only the Copilot preamble may differ) and
  the G-count invariant; wrapper projection unchanged — the role
  wrappers keep omitting the `agent` alias (the executors-cannot-spawn
  ceiling stays).

## 3. Covered acceptance criteria

- `AC-2` (US-025) — **Given** a live DevFlow Agent definition
  (`agents/squad/<id>/`), **When** the MainAgent installs it, **Then** it
  projects the platform wrapper and places it in that tool's spawn folder
  (`.github/agents/` on Copilot) so the agent is **spawnable** — broken
  on Copilot (REV-006 F-01), fixed by this Bolt.
- `AC-7` (US-025) — **Given** the four MainAgents, **When** they carry the
  lifecycle, **Then** only the destination folder + the wrapper format
  differ per platform — the Copilot specifics this Bolt documents.
- `AC-8` (US-025) — **Given** the projection, **When** the MainAgent
  installs, **Then** it reads the per-platform install mapping shipped in
  the kit's `agents/` docs and projects the wrapper itself — the
  VERIFICATION.md Copilot row is part of that self-contained mapping.
