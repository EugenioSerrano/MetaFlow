# US-000.BOLT-010 — Make BUG approval never-blocking (descriptions kept, blocking removed)

| Field        | Value |

| **Demo / completion evidence** | The recommended-approver descriptions (by nature + severity) are **still present** everywhere; every one is stated as **guidance, never a gate**, and **the author is never excluded**; zero blocking clauses remain; G-count 39×5; four-agent parity; root `devflow/` untouched |

---

## 1. Description

Change the distributed methodology (`distribution-kit/`) so that **BUG approval
is never a hard gate** — while **preserving the recommended-approver
descriptions**. The methodology continues to *describe* who should approve each
BUG by nature and severity (functional → Functional Analyst; non-functional
`critical` → Architect / Tech Lead; non-functional `high|medium|low` → any team
member). That description stays as **guidance**. What is removed, **in every
case**, is the *blocking*: the recommended role is never a precondition, and
**any qualified team member — the BUG's own author included — may record the
approval, at any severity and nature**.

Concretely, the last hard block is dropped: the **"self-approval is never
permitted on the `critical` route"** prohibition is removed, so the author may
approve even a `critical` BUG (the description still *recommends* Architect /
Tech Lead). The single-operator operability principle (US-014 — "role routing is
guidance, never a gate") is thereby made **uniform across every BUG route**,
including `critical`, and extended to always include the author.

This **completes** what REV-001 F-02 evidenced (a single-maintainer team can be
structurally blocked). SPEC-260821-0108 solved it for `high|medium|low`; its §14
kept `critical` **strict** ("the user's explicit decision"). This Bolt reverses
the **blocking** aspect of that decision — **not** the routing description: the
`critical → Architect/Tech Lead` recommendation stays, it simply stops being a
gate. As a by-product it dissolves the routing-consistency defect noticed in the
summary tables (the `critical` row that lacked the availability fallback).

**No new decision beyond the one recorded at `HITL-BOLT-READY-Approval`** (the
maintainer's "descriptions stay, blocking goes, author may approve"); this Bolt
is its mechanical application in one allowlist-aware pass.

## 2. Expected outcome and completion evidence

- **Objective:** every place the kit defines BUG approval keeps the recommended
  approver (by nature + severity) **as guidance** and makes explicit that it is
  **never a gate** — any qualified team member, **the author included**, may
  approve, at any severity and nature. No BUG is ever un-approvable.
- **Completion criteria:**
  - **Descriptions kept:** the recommended-approver text stays present —
    functional → Functional Analyst; non-functional `critical` → Architect /
    Tech Lead; non-functional `high|medium|low` → any team member.
  - **Blocking removed (every route):** each route statement carries the
    guidance-never-a-gate clause (recommended role, otherwise any qualified
    human) **and** is explicit that the **author is never excluded** — including
    the `critical` route.
  - **Last hard block gone:** the "self-approval is never permitted on the
    `critical` route" / "never the BUG's own author" / `critical`-route
    "Developer" prohibitions are **removed**.
  - **G29 repurposed, not deleted** (G-count stays **39**): its new form guards
    against *blocking* a BUG's approval — for lack of the recommended-role
    approver, on account of severity, or by excluding the author — rather than
    against the routing description. Exact wording is SPEC-level (HOW).
  - **T02 and the §3.0 operability-principle exception list** aligned: the
    `critical`/author separation is no longer a hard identity-separation rule.
    The **AI self-approval prohibition (G18/G24, ADR-008) is untouched** — a
    human author approving their own BUG is a different axis from an AI approving
    its own work.
- **Expected evidence (in the MEM):**
  - **Presence assertion** — the recommended-approver descriptions are still
    present at every location (they are kept, not deleted).
  - **Positive-coverage sweep (ADR-005) over the COMPLETE checkpoint set** —
    every checkpoint-map / §3.0 table / §3.0 narrative / agent-table statement
    of the BUG route carries the guidance-never-a-gate + author-included clause,
    **BUG and TC rows included** (the cell every prior sweep missed —
    root-cause of the BUG-001/003 family).
  - **Absence sweep** — zero blocking clauses remain in `distribution-kit/`
    ("self-approval is never permitted on the `critical` route"; "never the
    BUG's own author"; the `critical`-route "Developer" prohibition; any wording
    that makes a recommended role a precondition).
  - **G-count** = 39 in GUARDRAILS and each of the four agents (39×5).
  - **Four-agent body parity**; `git status` = only `distribution-kit/` + root
    governance records (kit-only, ADR-004).
- **Scope (`distribution-kit/` only):** the BUG route wherever it is defined —
  G29, T02, §2.16 (BUG nature/routing + dedicated-Bolt mirror), §3.0 (checkpoint
  table row + narrative "Who" bullet + operability-principle exception list),
  `GUARDRAILS.md` (checkpoint map + G29 + T02), the four agent definitions
  (checkpoint table row + G29 row + Bug-Fix-Protocol bullet), `bugs/README.md`,
  `bugs/TEMPLATE-BUG.md`, `ONBOARDING.md`, `functional/README.md`,
  `functional/bolts/TEMPLATE-BOLT.md`,
  `functional/user-stories/US-000-non-functional.md`. **Both** the functional
  and non-functional routes are in scope (the change is "never a gate + author
  included", applied to every route).
- **Exclusions:**
  - The recommended-approver **descriptions** — **kept**, not removed.
  - The **AI/agent self-approval prohibition** (G18/G24, ADR-008) — different
    axis; untouched.
  - The manifest **schemas** — no schema change; prose/policy only.
  - The root `devflow/` tree (ADR-004) — inherits at the next §5.16 migration.
  - v4.2 (released) — no backport unless a v4.2.x patch is separately decided.
- **Risks / controls:**
  - Over-broad sweep deletes a description instead of de-gating it → the
    completion criterion asserts the descriptions are **still present** (presence
    check), not just that blocks are gone.
  - Over-broad sweep touches the AI self-approval rule (G18/G24) → explicit
    scope guard; that axis is out.
  - Weakening review independence on `critical` (security-bearing) defects →
    **accepted by the maintainer's decision**; the recommendation still points
    at Architect/Tech Lead, and every approval records actor/role/timestamp/
    evidence (compensating control).
  - Partial sweep misses the BUG row again → **positive-coverage over the
    complete checkpoint set** (ADR-005), the explicit lesson from BUG-001/003.
  - G29 count drift → repurpose, never delete; assert 39×5.
