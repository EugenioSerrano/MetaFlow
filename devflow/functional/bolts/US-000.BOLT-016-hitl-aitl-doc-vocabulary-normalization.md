> as history.

## 1. Description

Complete the v5.0 migration's vocabulary re-expression. §5.16 already
converted the manifests' checkpoint names `HITL-*` → `AITL-*` on the basis
that **AITL ⊇ HITL** — a historical `HITL-*-Approval` **is** an `AITL-*-Approval`
in human mode, so the relabel is *truer, not falser*; only the label tracks
the version, the recorded facts are immutable. This Bolt extends that same
re-expression from the manifests (done) into the **mutable document bodies**
of the maintainer partition, so the documents read `AITL-*` consistently with
their own manifests.

---

## 2. Expected outcome and completion evidence

- **Objective:** in the maintainer partition (`devflow/`), every checkpoint
  reference used as **current vocabulary** in a mutable document reads
  `AITL-*`. The only literal `HITL` that remains is the kind the methodology
  deliberately keeps — and, by AITL ⊇ HITL, it already reads as AITL.
- **Completion criteria:**
  - **Mutable document bodies** (US and Bolt frontmatter `review:` /
    `acceptance_review:` blocks and their §6/§7 approval prose; REV / AREV /
    BUG / DISC bodies **not** in `_archive/`): zero `HITL-<CODE>-Approval`
    used as a current-vocabulary label.
  - **Recorded facts unchanged:** every `decided_by` actor, `decided_at` /
    `started_at` timestamp, decision `outcome` and evidence byte-identical —
    only the label token changed (diff proves it).
  - **Protected zones untouched** (git diff confirms no edits): all MEM
    bodies, all ADR bodies (G36), and everything under any `_archive/`
    (W20/G38).
  - **Framework rule/definition/history retained as-is:** G05 ("pre-v5
    `HITL-*` prefix is invalid"), the §1 "Human-in-the-Loop (HITL) is the
    default case" definition, the §5.16 migration protocol text, and
    historical statements — these name `HITL` on purpose and are **not**
    relabeled.
  - **Manifests:** already AITL from §5.16 — confirm still **0**
    `hitl_approvals` (no regression).
- **Expected evidence (in the MEM):**
  - Before/after `HITL-` sweep over `devflow/`, with each surviving hit
    classified: `relabeled` · `framework-rule/definition` · `migration-text` ·
    `MEM/ADR-body (frozen)` · `_archive (frozen)` · `history-prose`.
  - Diff excerpt proving only label tokens changed and no recorded fact moved.
  - `git status` restricted to mutable docs; MEM/ADR/`_archive` paths absent.
- **Scope (`devflow/` only):** mutable, non-MEM/ADR, non-`_archive` documents.
- **Exclusions:**
  - MEM bodies, ADR bodies, and all `_archive/` — **hard** (G36 /
    immutability / closure); they already read as AITL by AITL ⊇ HITL.
  - Recorded facts (actor / timestamp / outcome / evidence) — never altered.
  - Framework rule / definition / migration / history references to `HITL`.
  - `distribution-kit/` — out of scope (ADR-004; the product is already
    HITL-clean).
- **Risks / controls:**
  - A sweep touches a recorded fact or a protected body → the SPEC inventories
    exact tokens and the completion evidence proves facts unchanged and
    MEM/ADR/`_archive` untouched.
  - A legitimate framework `HITL` reference (G05, §1, §5.16) gets relabeled and
    breaks a rule → the SPEC distinguishes a **current-vocabulary label** from
    a **rule/definition/history** mention; only the former is relabeled.
