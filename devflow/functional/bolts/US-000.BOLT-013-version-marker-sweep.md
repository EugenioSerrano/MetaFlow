## 1. Description

Align the kit's version markers with its v5 content. The methodology content
is already v5-major (AITL checkpoints, manifest family v5, pre-v5 `HITL-*`
vocabulary, `H1–H6` removed), but its version stamps still read **4.2**.
This Bolt sweeps the **markers** — the places that declare the version — from
`4.2` to `5.0`, following the repo's version-bump procedure (the safe marker
patterns: `v4.2`, `Methodology version:** 4.2`, `Agent version:** 4.2`,
`version: "4.2"`), while leaving every **historical statement** as written
("removed in v4.2", "DORMANT/RESERVED (v4.2)") and every **section number**
("## 4.2") untouched.

Marker families in scope:

- `devflow/VERSION` — the single version declaration.
- Methodology frontmatter `version: "4.2"`.
- `GUARDRAILS.md` header `**Enforcing:** Avenga DevFlow v4.2` and the Related
  Documents line "(normative source, v4.2)".
- The `**Methodology version:** 4.2` header of **every** `README.md` and
  `INDEX.md` under `distribution-kit/devflow/` (the version-bump procedure
  requires the sweep across the whole tree; templates never carry it).
- The four agent definitions: `**Agent version:** 4.2 — implements
  methodology v4.2`, the `# Avenga DevFlow v4.2 (Methodology)` shared-body
  heading, and (where present) the `description` frontmatter
  ("follows the Avenga DevFlow v4.2 methodology").
- `AGENTS.md` source-of-truth line "(v4.2)".
- `ONBOARDING.md` header + source-of-truth line "(v4.2)".
- `avenga-devflow/INDEX.md` "Avenga DevFlow v4.2 — the complete methodology".

Explicitly **out of scope** (kept as written): historical statements ("the
UAT approval layer was removed in v4.2", "DORMANT / RESERVED (v4.2)", "in
v4.2 this whole layer is…"), section numbers that share the shape
("## 4.2 SPEC preparation and approval", "### 4.2 — [Another domain /
Category]"), the §3.12/§5.16 normative text about the family-major convention
("4.x keeps 4.0", "the family major may lead the methodology version"), and
the root `devflow/` tree (ADR-004 — it stays v4.2 until the §5.16 migration
at release).

No rule, checkpoint, guardrail or schema changes. G-count stays 39.

---

## 2. Expected outcome and completion evidence

- **Objective:** every version marker in `distribution-kit/` declares `5.0`;
  no historical statement or section number is altered; the kit's declared
  version matches its v5 content.
- **Completion criteria:**
  - `devflow/VERSION` = `5.0`.
  - `grep "Methodology version:**"` over `distribution-kit/` → every header
    reads `5.0`, none reads `4.2`.
  - The four agents: `Agent version:** 5.0 — implements methodology v5.0`,
    heading `# Avenga DevFlow v5.0 (Methodology)` — all four in lockstep.
  - Every remaining `4.2`/`v4.2` hit in `distribution-kit/` is either a
    historical statement or a section number (classification list verified).
  - **G-count** = 39×5 unchanged; **four-agent body parity** at the sanctioned
    2 lines per pair; `git status` = only `distribution-kit/` + root
    governance records (kit-only, ADR-004).
- **Expected evidence (in the MEM):**
  - Marker sweep result: counts before/after per marker family.
  - Residue classification: the complete list of remaining `4.2`/`v4.2` hits
    after the sweep, each classified `history` or `section-number`.
  - G-count 39×5 and parity outputs.
- **Scope (`distribution-kit/` only):** the marker families listed in §1.
- **Exclusions:**
  - Root `devflow/` tree (ADR-004) — stays v4.2 until the §5.16 migration.
  - Historical statements and section numbers (list above).
  - Guardrails, schemas, rules: untouched.
- **Risks / controls:**
  - Blind replace hits a historical statement → the SPEC applies only the
    marker patterns (never a bare `4.2` sweep); the residue classification
    after the sweep proves nothing historical changed.
  - The four agents drift if the heading/version edits land unevenly → parity
    diff must stay at 2 lines per pair.
  - A marker in a file the inventory missed → the sweep is defined by
    pattern, not by file list: every `**Methodology version:** 4.2` in the
    tree is replaced, then the residue grep proves completeness.
