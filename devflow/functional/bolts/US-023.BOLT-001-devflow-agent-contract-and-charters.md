---

## 1. Description

The kit gains the `devflow/agents/` family (G30-sanctioned by US-023): the
canonical definition contract (`agents/roles/<id>/agent.yaml` — the fields
of DISC-002 §5.1 with `executor` as the first-class default mode), the
shipped **Coordinator** (definition + charter — routes, delegates
production, spawns, records, **never signs**), and the **five role charter
templates** (functional-analyst, architect, developer, qa, reviewer) — each
**enumerating its role's productive outputs** and emphasizing
`modes: [executor]`, so a DevFlow Agent is chartered as a true actor that
produces the artifacts of its role (US-022 producer+approver reframe) with
approvals as a structured secondary attribute.

---

## 2. Expected outcome and completion evidence

- **Objective:** the canonical contract + Coordinator + five producer-first
  charter templates exist in the kit, ready for the wrapper generator
  (BOLT-002) and the roster (US-024).
- **Completion criterion:** the `agents/` folder tree exists with the
  contract structure, the Coordinator and the five templates; each template
  enumerates its role's outputs and carries `modes: [executor]` emphasis;
  the templates encode the **approver capability ceiling (T0/T1, no write
  paths, no transactional MCPs)** and the **`mcp_servers: []` default
  allowlist**; authority lives in structured fields
  (`modes`/`approves`/`capabilities`), never in charter prose (ADR-007).
- **Expected evidence:** the folder tree + the file diffs; a spot check that
  each charter template lists its productive outputs; the Coordinator
  charter states the separation of duties (never signs).
- **Scope:** `distribution-kit/devflow/agents/` (contract, Coordinator,
  charter templates, README).
- **Exclusions:** the wrapper generator + parity check (BOLT-002); the
  deployed per-platform wrappers (BOLT-003); the smoke test (BOLT-004); the
  roster schema/contents (US-024); the root `devflow/` (ADR-004).
- **Risks / controls:** charters drifting into authority prose — controlled
  by the structured-fields rule (ADR-007); templates not producer-first —
  controlled by the enumeration requirement (AC-1/AC-2).

## 3. Covered acceptance criteria

> Reference the ACs of the parent artifact — never write new ones here
> (§2.4, §2.6).

- `AC-1` (US-023) — **Given** the kit's `devflow/agents/` folder, **When** a
  maintainer inspects it, **Then** it contains `coordinator/`, `roles/`
  charter templates (functional-analyst, architect, developer, qa,
  reviewer) and a README; each charter template enumerates the productive
  outputs of its role and emphasizes `modes: [executor]`.
- `AC-2` (US-023) — **Given** the canonical definition contract, **When** a
  DevFlow Agent is defined, **Then** its `agent.yaml` carries the fields of
  DISC-002 §5.1 with `executor` (production) as the first-class default and
  the charter body stating WHAT I PRODUCE.
- `AC-4` (US-023) — **Given** the identity model, **When** authority is
  expressed, **Then** it lives in structured fields; the productive mandate
  is the charter.
- `AC-5` (US-023) — **Given** the Coordinator, **When** the kit ships it,
  **Then** it delegates production, spawns, records — and never signs
  (ADR-008 separation of duties).
- `AC-7` (US-023) — **Given** capability tiers, **When** an agent acts as
  approver, **Then** it runs at T0 (at most T1 with pinned trusted
  sources), no write paths, no transactional MCPs — **encoded in the
  charter templates and the agent.yaml capability fields this Bolt
  delivers** (the injection-forged-approval defense, ADR-008 §3.6; the
  rules on the `capabilities` field that AC-2 defines).
- `AC-8` (US-023) — **Given** MCP access, **When** an agent declares MCP
  servers, **Then** each server is named and allowlisted
  (`mcp_servers: []` by default) — **encoded in the contract's
  `mcp_servers` field and the templates' defaults this Bolt delivers** (no
  implicit or unrestricted MCP exposure).
- `AC-11` (US-023) — **Given** the kit partition, **When** this Bolt lands,
  **Then** only `distribution-kit/` changes.
