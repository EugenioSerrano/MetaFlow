## 1. Description

Bump every version marker of the distribution kit (`distribution-kit/`) from
**5.0** to **5.1** — the release-line marker sweep that follows the root
AGENTS.md "Version bump procedure" (restored in the maintenance partition) and
the US-000.BOLT-013 precedent (4.2→5.0). The kit's `devflow/VERSION`, every
`**Methodology version:** 5.0` header of `README.md`/`INDEX.md` (templates
never carry one), `GUARDRAILS.md` header (`Enforcing: Avenga DevFlow v5.0`)
and footer, `ONBOARDING.md`, the methodology frontmatter `version: "5.0"`, the
four agent definitions (shared `# Avenga DevFlow v5.0 (Methodology)` heading,
`**Agent version:** 5.0 — implements methodology v5.0`, and the preamble
description mentions in gh-copilot/open-code) and the kit `AGENTS.md`
source-of-truth line all read 5.1. The **manifest family is deliberately
untouched**: `schema_version` stays `"5.0"` — the `<major>.0` convention
(schema changes only on a major; the v5 family keeps 5.0 on the 5.1 line).

---

## 2. Expected outcome and completion evidence

- **Objective:** the kit's version markers all read 5.1, with the manifest
  family untouched at `schema_version: "5.0"`.
- **Completion criterion:** every carrier enumerated in the SPEC reads 5.1;
  zero residue of the 5.0 marker patterns remains outside the declared
  allowlist (schema family, history statements, section references).
- **Expected evidence:** RED (before the fix, this V-Bounce): the inventory
  greps with counts and line numbers (VERSION = 5.0; 71 README/INDEX headers;
  GUARDRAILS header+footer; ONBOARDING L3; frontmatter L3; 10 agent spots;
  kit AGENTS.md L6). GREEN (after the fix): the same greps return the 5.1
  patterns with matching counts, the absence sweep for the 5.0 patterns is
  empty outside the allowlist, `schema_version: "5.0"` still present in the 3
  schemas + 5 manifest templates + the §3.12 statement, four-agent parity
  (shared-body diff = sanctioned 2 lines/pair), G-count 39×5, `git status`
  shows only `distribution-kit/` files changed (plus governance artifacts).
- **Scope:** `distribution-kit/` only — the version carriers above; no rule,
  schema, template, guardrail-row or behavioral change.
- **Exclusions:** the root `devflow/` maintenance partition (stays 5.0 until
  the next §5.16 migration), the root `README.md` (already 5.1), the JSON
  schemas and `TEMPLATE-MANIFEST-*.json` (`schema_version` stays "5.0"),
  templates (never carry markers), `CHANGELOG.md` history and every statement
  *about* an older version ("versions up to 4.1…", "From 4.2 on…") and section
  references (`§2.4.1`, `§4.1`, `§4.10`, `§5.16`).
- **Risks / controls:** blind replace of a bare `5.0` would corrupt section
  references and history → the SPEC uses the safe patterns only (`v5.0`,
  `Methodology version:** 5.0`, `Agent version:** 5.0`, `version: "5.0"`,
  `Enforcing:** Avenga DevFlow v5.0`, `(v5.0)`) with an absence sweep
  (ADR-005 phrase-family discipline).
