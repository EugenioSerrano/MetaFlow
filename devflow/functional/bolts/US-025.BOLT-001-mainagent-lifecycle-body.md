## 1. Description

Give the four MainAgents (kit `CLAUDE.md`, `SKILL.md`,
`AvengaDevFlow.agent.md`, `AvengaDevFlow.md`) the **lifecycle capability
as text**: one byte-identical shared-body section instructing the
Coordinator how to **install, create and delete** DevFlow Agents — so the
behavior the adopter smoke test achieved by model diligence (REV-005
C-01: the MainAgent derived the flow from the family docs alone) becomes
**contract**, identical on every platform.

---

## 2. Expected outcome and completion evidence

- **Objective:** a shared-body lifecycle section, byte-identical across
  the four MainAgents, covering: **install** (project a `squad/`
  definition into this platform's wrapper per the shipped mapping and
  place it in the spawn folder), **create** ("create me a reviewer" →
  scaffold from `TEMPLATE-new-role/` + the closest example into
  `agents/squad/<id>/` → add the actor to the roster as an
  **executor-only draft** → install), **delete** (check the roster's N:1
  references first — never break a referenced definition — then remove
  wrapper/definition, keeping roster + INDEX consistent), plus the
  **MainAgent-identity clause** (MainAgent ≡ AvengaDevFlow, one per tool
  ≡ the Coordinator — inline synonym, US-025 AC-10) and the **governance
  clauses** (executor lifecycle = living data, no Bolt; approver
  authority = the human's roster configuration act, never the agent's;
  installing never enables approval).
- **Completion criterion:** the section present in the four files with a
  **single hash** (byte-identical); the identity clause and the
  governance clauses readable inline; role agents carry none of it
  (US-025 AC-1).
- **Expected evidence:** the four-agent byte-sync diff (single md5 of the
  section); G-count 39 × 4; **scoped self-containment** — the NEW section
  adds zero maintenance-partition references (the clauses cite kit text,
  never ADRs), and the four files END with zero such references other than
  the kit's own `US-000` (see the cleanup in scope); the section's
  cross-references (`agents/`, `actors/`, `VERIFICATION.md`) resolve.
- **Scope:** the shared body of the four MainAgent files — the new
  lifecycle section, **plus the cleanup of the pre-existing
  maintenance-partition references in that same shared body** (verified
  baseline: the Coordinator paragraph's `ADR-008` and `US-023 AC-6`
  mentions — replaced with kit-internal wording, per US-025 AC-9; the
  kit's own `US-000` references and the naming-table's fictional example
  ids like `US-012.BOLT-003-…` are framework text and stay). The
  **per-platform preambles'** references (`ADR-007 §3.4`, `US-023 AC-6`)
  and their **stale pre-built-wrapper list** (`Agent(architect-agent, …)`
  — deleted by the ship model) are **BOLT-002's** (per-platform surface),
  noted here so they are not lost.
- **Declared vs completed:** the shared body **declares** the three flows
  (install/create/delete); the full per-platform capability (AC-2) and the
  delete-safe depth (AC-4) **complete in BOLT-002/BOLT-003** — AC-2/3/4
  are not claimable Done after this Bolt alone.
- **Exclusions:** the per-platform specifics — destination folder, wrapper
  format, projection mapping details, `inherit` handling (US-025.BOLT-002);
  the delete-safe tooling depth (BOLT-003); the kit GUARDRAILS G07 scoping
  text (BOLT-005); the pilot (BOLT-004).
- **Risks / controls:** wording drift between the four — controlled by the
  byte-sync hash check (US-016 discipline); accidental guardrail-table
  changes — controlled by the G-count invariant; scope bleed into
  per-platform detail — controlled by the BOLT-002 exclusion.

## 3. Covered acceptance criteria

- `AC-1` (US-025) — the lifecycle lives **only in the four MainAgents** as
  a byte-identical shared body; role agents carry none of it.
- `AC-5` (US-025) — executor install/create/delete = living data; approver
  creation/authority change = governed (the human's roster act); installing
  an already-enabled approver's wrapper = execution of that act.
- `AC-6` (US-025) — installing never enables approval; the safe default
  holds.
- `AC-10` (US-025) — the MainAgent ≡ AvengaDevFlow ≡ Coordinator
  equivalence stated inline, consistent and byte-sync across the four.
- `AC-9` (US-025, partial — the four MainAgents' surface) — no
  maintenance-partition references: the new section adds none and the
  pre-existing ones in the shared body are cleaned in this pass.

> The shared body declares the install/create/delete flows; AC-2/AC-3/AC-4
> are covered by BOLT-002 (per-platform capability) and BOLT-003
> (delete-safe) — never claimable from this Bolt alone.
