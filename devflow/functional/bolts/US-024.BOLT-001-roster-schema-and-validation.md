## 1. Description

The `actors/` family (folder created by US-022) gains the standard DevFlow
shape: **`TEMPLATE-ACTOR`** (the template for creating an actor),
`roster.schema.yaml` (validates an actor file), **`INDEX.md`** (lists the
project's actors, like every family), the `project_policy` roster file
(`aitl_enabled_checkpoints`, the `human_only` floor) and an example actor
file. **Each actor is its own file** `actors/<actor-id>.yaml` (naming
N-rule) — humans and agents as peers, each carrying `id`, a project-chosen
`name`, `role`, `model`, `modes`, `approves` (agents also a `definition`
pointer). The **production mapping is derived from `role`** (the single
role → artifacts mapping in the charter templates, US-023 BOLT-001, and
§3.0.1) — **no per-agent `produces` field**; the `definition` is reusable
(N actors : 1) and each actor's `model` is per-instance. Validation: each
actor file validates against the schema (validator tooling, US-012 family);
a malformed file fails fast and the safe default (humans) applies.

---

## 2. Expected outcome and completion evidence

- **Objective:** a schema that makes the roster a mechanically checkable
  team map — the one file the Coordinator (US-023) reads to resolve roles,
  production and approval lookups.
- **Completion criterion:** `actors/` holds `TEMPLATE-ACTOR`,
  `roster.schema.yaml`, `INDEX.md`, the `project_policy` file and an
  example actor file; **one file per actor** created from the template and
  listed in the INDEX, carrying the reconciled field set (no `produces`
  field — outputs derived from `role`; `definition` reusable N:1; `model`
  per-instance); the example actor file validates; a malformed one fails
  fast.
- **Expected evidence:** the schema + example diffs; the validation run
  (valid example passes, malformed fails); the grammar forms
  (`human:<user>` / `agent:<id>`, ADR-010).
- **Scope:** `distribution-kit/devflow/actors/` (`TEMPLATE-ACTOR` + schema +
  `INDEX.md` + `project_policy` file + example actor file) + the validation
  integration (US-012 family).
- **Exclusions:** the AITL-enable ADR template + resolution-rule text
  (BOLT-002); the US-001 absorption (BOLT-003); the root `devflow/`
  (ADR-004).
- **Risks / controls:** schema/grammar divergence — controlled by reusing
  the ADR-010 forms; a `produces` field sneaking back in — controlled by
  the reconciled field set (US-024 AC-1).

## 3. Covered acceptance criteria

> Reference the ACs of the parent artifact — never write new ones here
> (§2.4, §2.6).

- `AC-1` (US-024) — **Given** the kit's `actors/` folder, **When** a project
  builds its team, **Then** it holds `TEMPLATE-ACTOR` + `roster.schema.yaml`
  + `INDEX.md` + the `project_policy` file, with **one file per actor**
  (`actors/<actor-id>.yaml`, from the template, listed in the INDEX);
  humans + agents as peers, each with a project-chosen `name`; productive
  outputs **derived from `role`** (no `produces` field); `definition`
  **reusable N:1**; `model` **per-instance**.
- `AC-8` (US-024) — **Given** validation, **When** an actor file is edited,
  **Then** it validates against `roster.schema.yaml` (validator tooling,
  US-012 family) — a malformed actor file fails fast and the safe default
  (humans) applies until fixed.
- `AC-9` (US-024) — **Given** the actor grammar, **When** the roster
  records actors, **Then** it uses the `human:<user>` / `agent:<id>` forms
  consistent with `checkpoint_approvals[]`.
