---

## 1. Description

Bring the **per-platform half** of the lifecycle up to the ship model:
each MainAgent's platform preamble (the only part that legitimately
differs across the four) tells ITS tool's spawn folder, wrapper format and
how to project from `squad/` — replacing the stale pre-built-wrapper era
text — and the shipped mapping (`agents/VERIFICATION.md`) gains the three
precision items the adopter smoke test proved missing: the exact
permission-block derivation, the `model: inherit` projection handling, and
the OpenCode platform behavior notes.

---

## 2. Expected outcome and completion evidence

- **Objective:**
  1. **The four platform preambles updated** (each MainAgent's
     spawn-topology paragraph): the tool's spawn folder + wrapper format +
     "project from `agents/squad/` per the VERIFICATION.md mapping";
     the **stale pre-built-wrapper text removed** (Claude's
     `Agent(architect-agent, …)` list; Codex's `.codex/agents/*.toml`
     role-agents mention); the **maintenance references cleaned**
     (`ADR-007 §3.4` and `US-023 AC-6` in all four; `DISC-002` in
     Codex's) — completing **US-025 AC-9** on the four files.
  2. **VERIFICATION.md precision** (the shipped mapping):
     (a) the **permission-block derivation** — how a definition's
     `capabilities.tools` allowlist becomes each platform's wrapper
     permissions, including the deny-set, so two projections of one
     definition cannot differ (REV-005 F-14 — the `list: allow` drift);
     (b) **`model: inherit` handling** — resolved at projection time to
     the session's model per platform (it is not a catalog value and
     cannot land verbatim in a wrapper), with the guidance line: pin a
     **distinct** model for reviewer/approver-class agents (REV-005
     F-09); (c) the **OpenCode platform notes** — subagents do not appear
     in the Tab picker (primary agents only; visible via ctrl+X /
     `opencode agent list`; invoked through the Coordinator's task tool —
     the spawn topology working as designed), a session reload registers
     new agents, headless `opencode run` registration unverified
     (REV-005 F-13).
- **Completion criterion:** the four preambles current and clean; the
  mapping carries the three precision items; the shared body untouched
  (its hash from the BOLT-001 V-Bounce unchanged).
- **Expected evidence:** kit-wide sweep — **zero maintenance-partition
  references in the four MainAgents** (the framework examples and the
  kit's own `US-000` stay); a stale-text sweep (no `architect-agent`-list,
  no `.codex/agents/*.toml`-as-shipped mentions); the shared-body section
  hash **unchanged** vs the BOLT-001 evidence; the preambles each name
  their spawn folder + VERIFICATION.md; no BOM.
- **Scope:** the four platform preambles + `agents/VERIFICATION.md`.
- **Exclusions:** the shared lifecycle body (BOLT-001, delivered); the
  delete-safe depth (BOLT-003); the kit GUARDRAILS G07 scoping (BOLT-005);
  the pilot (BOLT-004). The examples' `capabilities` fields (v2 hardening).
- **Risks / controls:** touching the shared body by accident — controlled
  by the section-hash-unchanged gate; per-platform wording diverging in
  meaning — controlled by a common preamble content checklist in the SPEC
  (same items, platform-specific values).

## 3. Covered acceptance criteria

- `AC-2` (US-025) — install lands the wrapper in **that tool's** spawn
  folder: the preamble names it and the wiring to the mapping.
- `AC-7` (US-025) — only the destination folder + wrapper format differ
  per platform; the lifecycle logic stays byte-identical (the shared body
  untouched — hash gate).
- `AC-8` (US-025) — docs-primary: the mapping is self-contained in the
  kit and now precise enough to project deterministically (permissions +
  inherit); the N×4 parity check stays the safety net; the compiled
  generator stays optional.
- `AC-9` (US-025, completion) — with the preambles cleaned, the four
  MainAgents carry **zero** maintenance-partition references.
