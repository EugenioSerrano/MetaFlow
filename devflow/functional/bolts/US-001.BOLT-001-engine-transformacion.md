---

## 1. Description

Entrega el engine de transformación y su CLI: carga el diccionario de reglas
(`mapping.json`), aplica las reglas (`rename`, `regex_rename`, `remove`,
`path_rename`) en orden longest-first sobre contenido y rutas del kit de
entrada, con modos **dry-run** (plan sin escribir ni borrar) y **ejecución
real** (borra el contenido previo de `distribution-kit/` y escribe el kit
nuevo), junto con los tests unitarios del engine.

---

## 2. Expected outcome and completion evidence

- **Objective:** transformar `input-kit/` → `distribution-kit/` aplicando el
  diccionario completo, con la versión de salida = entrada − 4 (5.1 → 1.1) y
  sin residuos de corridas anteriores.
- **Completion criterion:** sobre un fixture E2E (kit pequeño controlado), el
  pipeline produce un árbol donde los únicos cambios son los del diccionario;
  el dry-run no escribe ni borra nada; la ejecución real reemplaza el
  contenido completo de `distribution-kit/`.
- **Expected evidence:** salida de CLI (dry-run y real), árbol transformado en
  `distribution-kit/`, suite de tests unitarios en verde (orden de reglas,
  variantes de caso, regex de checkpoints, renames de rutas, remociones,
  borrado de salida).
- **Scope:** engine de reglas (los 4 tipos, orden longest-first), carga de
  `mapping.json`, renames de rutas (archivos y carpetas), CLI con
  `--dry-run`, borrado de salida en modo real (validando que sea
  `distribution-kit/`), tests unitarios.
- **Exclusions:** verificador de tokens prohibidos (BOLT-002), reporte de
  transformación (BOLT-002), aceptación E2E contra el kit real completo
  (BOLT-002).
- **Risks / controls:** un replace mal ordenado rompe el texto → orden
  longest-first por construcción + tests; borrado destructivo → solo se borra
  `distribution-kit/` (ruta validada) y nunca en dry-run.

## 3. Covered acceptance criteria

> ACs del parent — no se escriben ACs nuevas (§2.4, §2.6).

- `AC-1` (US-001) — **Given** un kit de AvengaDevFlow completo en `input-kit/`, **When** se ejecuta el pipeline, **Then** `distribution-kit/` contiene el kit MetaFlow equivalente con versión = entrada − 4 (5.1 → 1.1).
- `AC-2` (US-001) — **Given** el diccionario como datos editables, **When** se agrega una regla, **Then** se aplica sin modificar el código del engine.
- `AC-3` (US-001) — **Given** reglas de longitudes distintas, **When** se aplican, **Then** la cadena más larga se reemplaza primero y nada queda parcialmente transformado.
- `AC-4` (US-001) — **Given** códigos de checkpoint variables, **When** se transforma, **Then** pasan a `CP-<CODE>-Approval` conservando el código variable.
- `AC-5` (US-001) — **Given** contenido marcado para remoción, **When** se transforma, **Then** se elimina y queda disponible para el reporte (BOLT-002).
- `AC-6` (US-001) — **Given** un kit y el diccionario, **When** se ejecuta dry-run, **Then** se muestra el plan sin escribir **ni borrar** nada.
- `AC-10` (US-001) — **Given** una ejecución real, **When** comienza, **Then** el contenido completo de `distribution-kit/` se borra antes de escribir (cero residuos; solo esa carpeta).
