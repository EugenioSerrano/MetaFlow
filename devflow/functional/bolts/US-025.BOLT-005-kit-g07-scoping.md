---

## 1. Description

Express in the kit's guardrail surfaces the scoping ADR-013 decided:
**the agent lifecycle is operational configuration, not a code change
under G07** — with its non-negotiable bounds — so an adopter's agent no
longer has to resolve a divergence between the READMEs (living data) and
an unscoped G07, silently or otherwise (the exact failure mode the
adopter smoke test proved, REV-005 F-02 🔴).

---

## 2. Expected outcome and completion evidence

- **Objective:** the G07 scoping stated consistently in the kit's TWO
  guardrail surfaces:
  1. **`distribution-kit/devflow/GUARDRAILS.md`** — the G07 row's agent
     response gains the scope clause: installing/creating/deleting
     DevFlow Agents within the agent system (`devflow/agents/` squad
     definitions + wrappers, `devflow/actors/` actor files + roster
     listings) is **operational configuration — living data** (the same
     class as roster/prompt updates, §5.12), **bounded**: never the
     shipped examples/templates edited in place, never outside the agent
     system, and **approver authority remains the human's roster act** —
     everything else G07 covers stays absolutely blocked.
  2. **The four MainAgents' compressed G07 row** (byte-sync ×4) — the same
     scope in row-length form, so the agents' own tables agree with their
     lifecycle section and with GUARDRAILS.
- **Completion criterion:** both surfaces carry the scoping with
  consistent semantics; the guardrail's blocking force for actual code is
  untouched; **G-count 39** in GUARDRAILS and in the four agents.
- **Expected evidence:** the diffs; G-count 39 ×5 surfaces; the four-agent
  G07 row hash identical; the shared lifecycle section hash **unchanged**
  (`cd24754c320d…` — the scoping touches the guardrail table row, not the
  section); self-containment (the kit text cites §5.12/the roster rule,
  never ADRs — the ADR citation lives in THIS Bolt, per ADR-013 §3.7);
  a consistency read-through (GUARDRAILS row ⇔ agents' row ⇔ the lifecycle
  section's living-data clause — one semantics, three altitudes); no BOM.
- **Scope:** the G07 row in `GUARDRAILS.md` + the G07 row in the four
  MainAgents (and, if the sweep finds another kit surface stating G07's
  absolutism verbatim, that line — reported in the MEM).
- **Exclusions:** every other guardrail row; the lifecycle section
  (hash-locked); the methodology §3.2 prose unless the sweep proves a
  direct contradiction (reported first, per the stop condition); the pilot
  (BOLT-004).
- **Risks / controls:** weakening G07's absolutism for real code —
  controlled by the clause's structure (the scope DEFINES lifecycle acts
  as not-code; everything else stays "no exceptions"); intra-kit
  divergence — controlled by the three-altitude read-through + byte-sync.
