---

## 1. Description

Deepen the Delete flow BOLT-001 declared into a **checkable contract**:
define the consistency invariants that install/create/delete must
preserve, the exact reference-check procedure (who points at what, in
which files), and the edge cases — documented in the family docs the
Coordinator reads (`agents/squad/README.md` as the operating surface,
cross-referenced from `agents/README.md`).

---

## 2. Expected outcome and completion evidence

- **Objective:** the family docs gain the **lifecycle consistency
  contract**:
  1. **The invariants** — after any lifecycle act, the four legs agree:
     a wrapper in a spawn folder ⇔ its live definition in
     `agents/squad/<id>/` ⇔ its row in `agents/INDEX.md` ⇔ (when the
     agent is a team member) its actor file + `roster.yaml` listing. No
     leg exists orphaned.
  2. **The N:1 reference-check procedure** (before delete): enumerate the
     actor files whose `definition:` points at the target
     `squad/<id>/agent.yaml` AND the `roster.yaml` listings of those
     actors — a definition referenced by any listed actor is **never
     removed**; only its wrapper may be (the actor then stops being
     spawnable on that platform until reinstalled).
  3. **The edge cases** — delete an agent whose definition is shared
     (remove the actor + wrapper, keep the definition); delete the LAST
     actor of a definition (definition may go); a wrapper without a
     definition or a definition without an INDEX row (repair per the
     invariants); the actor-file-not-listed case (not in the team —
     ADR-014 membership rule — flag, never silently adopt).
- **Completion criterion:** the contract present, self-contained, and
  consistent with the shared body's Delete flow wording (no
  contradictions); the shared lifecycle body **untouched**.
- **Expected evidence:** the docs diff; a consistency read-through
  (contract vs the shared body's flows — no drift); the pinned-hash gate
  (`cd24754c320d…` ×4 unchanged); self-containment (0 maintenance IDs);
  no BOM.
- **Scope:** `distribution-kit/devflow/agents/squad/README.md` (the
  contract's home) + a pointer line in `agents/README.md` (and
  `actors/README.md` if a cross-reference is needed).
- **Exclusions:** the four MainAgents (their Delete flow already points
  at the roster check — this Bolt writes the contract it points to); any
  tooling/automation of the check (the validator family, US-012, later);
  the pilot (BOLT-004).
- **Risks / controls:** contract-vs-body drift — controlled by the
  read-through check + the hash gate proving the body untouched.
