---

## 1. Description

Close the eight quality gaps that approved **REV-002** found in the v5.0 kit
(`distribution-kit/`): the AITL governance wording that still reads "human-only,"
the 26 `HITL-*` residues the US-021 sweep missed, the `schema_version` self-contradiction,
and four small hygiene defects — all as documentation alignment to already-governing
artifacts, in one allowlist-aware pass. **No new decision is introduced** (ADR-008,
the manifest schema and the §3.15 vocabulary already govern the target state).

---

## 2. Expected outcome and completion evidence

- **Objective:** the v5.0 kit is internally consistent and truthfully "fully AITL" —
  every REV-002 finding (F-01…F-08) closed, with F-04 resolved to match ADR-008.
- **Completion criterion — each finding closed:**
  - **F-04** — the kit's checkpoint-governance wording states **"human by default,
    virtual agent only by explicit valid configuration"** (ADR-008 §3.1–§3.4),
    replacing every unqualified "human-only / never delegated to AI / always a named
    human" assertion in the §3.0 charter tables, `GUARDRAILS.md`, and `AGENTS.md`.
    The hard identity rules (no self-approval, safe default, never fabricate a human)
    remain intact.
  - **F-01** — the 26 non-allowlisted `HITL-*` mentions (the language-policy line ×25
    + T12) read `AITL-*`; the §4a allowlist zones are unchanged (G36 history preserved).
  - **F-03** — §3.12 states the shipped manifest-family `schema_version`, and the
    "`<major>.0` of VERSION" wording is reconciled with the family having led to `5.0`
    on the schema change while the methodology is 4.2.
  - **F-05** — the AITL/virtual-approver citation points at the correct section
    (the AITL charter), in the methodology and the four agents.
  - **F-06** — the AREV `cancelled` status has a home in the AREV README lifecycle
    table and an INDEX bucket (matching the template and §3.15).
  - **F-07** — the corrupted example-manifest comment is fixed.
  - **F-08** — the "release suite" wording is consistent between GUARDRAILS and the methodology.
- **F-02 (verification method, not a doc edit):** the completeness sweep excludes the
  allowlist **by zone** (file / rule / section / defining sentence), never by the literal
  token `HITL-*` — this is the acceptance evidence for F-01 and prevents the false-GREEN
  from recurring.
- **Expected evidence (in the MEM):** before/after counts; the zone-scoped absence sweep
  = zero non-allowlisted `HITL`; a migrated `HITL-*` manifest still validates against the
  unchanged v5 schema (G36); the 5 `TEMPLATE-MANIFEST-*.json` still validate; four-agent
  shared-region byte-identity + G-count 39×5; `git status` shows only `distribution-kit/`
  + root governance records (kit-only, ADR-004).
- **Scope:** documentation edits inside `distribution-kit/` only.
- **Exclusions:** the `manifest-v5-*.schema.json` enum `HITL-*` (history support, G36); the
  §4a allowlist zones; the root `devflow/` tree (ADR-004); **enabling** virtual approvers
  (registry / roster / Coordinator / pilot — later USs, ADR-008 §3.9). This Bolt states the
  precept correctly; it does not build the enablement.
- **Risks / controls:** over-broad sweep touching allowlist/history → zone-scoped exclusion
  + G36 validation; charter-wording change misread → bounded to ADR-008's exact precept, no
  new rule; four-agent drift → byte-identity + G-count check.

## 5. Does this Bolt need splitting?

No. The eight findings are one class (v5.0 kit documentation consistency) delivered by a
single allowlist-aware pass with one completion demo (the zone-scoped absence sweep +
schema validation + four-agent parity). They are not independently *acceptable* outcomes:
splitting would multiply SPEC/V-Bounce overhead for edits that interleave on the same files
(§3.0 charter, GUARDRAILS, the four agents) and share one verification. Estimated active
delivery (AI-native rule, §2.4): one V-Bounce, ~2–4h including SPEC + review. Sequencing
**F-04 first** matters (it is the prerequisite for the later virtual-approver USs), but that
is intra-Bolt ordering, not a split.
